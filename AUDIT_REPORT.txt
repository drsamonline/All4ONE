Audit bug fixed after this report's first run: the source-tree cache check
scanned every __pycache__ on disk, including untracked, gitignored ones that
the interpreter itself writes during a normal `python audit.py` run — so the
gate failed spuriously ("Build tree contains __pycache__") unless invoked as
`python -B`. The check now flags only tracked __pycache__/.pyc files; ZIP
cache scanning is unchanged.

Project hardening pass (see CHANGELOG.md [Unreleased]):
  - Added LICENSE (MIT), SECURITY.md, .editorconfig, pyproject.toml (ruff
    config only — the project is not a pip package).
  - Added .github/workflows/ci.yml: Linux validation job running ruff
    (advisory) plus hard gates on audit.py and the smoke-test suite.
  - audit.py version gate rewritten to static text matching against
    VERSION.txt for core/__init__.py, config.json AND build.spec (the old
    import-based check risked re-introducing the __pycache__ self-sabotage
    bug class); verified it fails loudly when any literal is desynced.
  - Silent `except Exception:` fallbacks in core/extended_ops.py (JSON
    input parse, psutil probes, clipboard teardown) now log debug detail
    before falling back; console output stays clean via ConsoleFormatter.

CI failure post-mortem (Linux + Windows builds failed on GitHub): a later
commit force-added tracked build/runtime clutter — three __pycache__/*.pyc
files and an empty logs/utility_suite.log — and emptied .gitignore, which
deleted the __pycache__/*.pyc and logs/* ignore rules. audit.py's tracked-
cache gate then correctly failed every CI job ("Build tree contains tracked
__pycache__/.pyc files"). Fixed by: untracking all four files, restoring a
complete .gitignore, extending audit.py with a companion gate that rejects
any tracked non-.gitkeep file under logs/, adding a fail-fast "No committed
build/cache artifacts" step to ci.yml, and moving the audit step ahead of
the ZIP rebuild in build-windows-exe.yml so clutter is reported first.

Fixes applied in this pass (see CHANGELOG.md for full detail):
  - count / download / filetype / hexview / integrity-baseline: now give a
    friendly message instead of a raw errno/traceback when pointed at a
    directory or an invalid URL.
  - Console logging no longer prints full Python tracebacks for routine,
    already-handled tool errors; full detail is still kept in the rotating
    file log for developers.
  - GUI launch ('utility_suite gui' and the no-argument default) now fails
    gracefully with an actionable message if tkinter is unavailable or no
    display is present, instead of an unhandled exception.
  - security_tools/secure_delete.py renamed to integrity_baseline.py to
    match what the module actually does.
  - GUI: added a confirmation prompt before running tools that can delete
    or overwrite data, plus File/Folder browse buttons that insert a
    correctly-quoted path into the argument field.
