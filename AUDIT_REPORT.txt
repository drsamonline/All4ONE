2026-10 hardening pass (this release, 3.0.6):
  - Repository hygiene restored (again). The committed .gitignore had regressed
    to a 7-byte "(empty)" stub, so __pycache__/build_single_exe.cpython-312.pyc
    and a non-empty logs/utility_suite.log had been force-added back into the
    tree — the exact failure documented as fixed in earlier passes. Both
    artifacts are removed, a complete .gitignore is restored, and audit.py now
    FAILS when any required ignore pattern is missing, so the regression cannot
    recur silently.
  - audit.py tracked-artifact gate hardened. It previously ran `git ls-files`
    without checking the exit code, so on a machine without git the output was
    empty and the gate passed vacuously. A missing or failing git is now a hard
    audit failure, and the .gitignore content is checked directly.
  - Templated tool descriptions eliminated. 240 of 551 descriptions were
    machine-generated boilerplate ("X: x as structured JSON output.",
    "Locate <thing> on disk or in scope.", "Compile a readable … report
    report."); all 551 are now unique, human-written one-liners, and audit.py
    rejects the known templates outright (uniqueness alone was too weak a gate).
  - Version-sync gate widened. The audit now also verifies version_info.txt
    (prodvers tuple), README's version badge, AUTHORS.md, AUDIT_REPORT.txt and
    COMPILATION.md against VERSION.txt, closing the doc-drift class of bug
    (AUTHORS.md previously advertised "3.0.0" while VERSION.txt said 3.0.5.1).
  - Shell-injection surface removed in system_utils/net_reset.py. The adapter
    name is now validated against a strict allow-list before it is interpolated
    into the elevated PowerShell command, matching the "no shell strings"
    guarantee stated in SECURITY.md.
  - GUI output is streamed. core.tool_registry.run_tool() now forwards a tool's
    stdout/stderr to the GUI callback line-by-line as it is produced instead of
    buffering the whole run in memory and replaying it on completion, so
    long-running tools (servers, watchers, monitors) show output live.
  - Dead code removed in core/capability_checker.py (a `… or True` tautology in
    the "python" dependency probe).
  - tests/test_all_tools.py no longer writes logs/sweep_results.json into the
    source tree; the sweep report is written to the system temp directory.
  - Documentation and claims aligned with the code: the README and
    DEVELOPER_GUIDE now describe the shared-engine architecture honestly (most
    tools are thin adapters over core/extended_ops.py), and the stale
    "539 expansion tools" docstring in extended_ops.py was corrected.

Qualification note (unchanged since 2.1.2): this audit environment is Linux,
so native Windows integrations remain dependency-gated and statically verified
rather than executed against a live Windows kernel.
