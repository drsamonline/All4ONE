Audit bug fixed after this report's first run: the source-tree cache check
scanned every __pycache__ on disk, including untracked, gitignored ones that
the interpreter itself writes during a normal `python audit.py` run — so the
gate failed spuriously ("Build tree contains __pycache__") unless invoked as
`python -B`. The check now flags only tracked __pycache__/.pyc files; ZIP
cache scanning is unchanged.

Fixes applied in this pass (see CHANGELOG.md for full detail):
  - count / download / filetype / hexview / integrity-baseline: now give a
    friendly message instead of a raw errno/traceback when pointed at a
    directory or an invalid URL.
  - Console logging no longer prints full Python tracebacks for routine,
    already-handled tool errors; full detail is still kept in the rotating
    file log for developers.
  - GUI launch ('utility_suite gui' and the no-argument default) now fails
    gracefully with an actionable message if tkinter is unavailable or no
    display is present, instead of an unhandled exception.
  - security_tools/secure_delete.py renamed to integrity_baseline.py to
    match what the module actually does.
  - GUI: added a confirmation prompt before running tools that can delete
    or overwrite data, plus File/Folder browse buttons that insert a
    correctly-quoted path into the argument field.

Qualification note (unchanged since 2.1.2): this audit environment is
Linux, so native Windows integrations remain dependency-gated and
statically verified rather than executed against a live Windows kernel.
